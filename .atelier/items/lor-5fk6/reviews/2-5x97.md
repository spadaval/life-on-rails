## Finding 4: Completing a searched flagged task must also clear its queue flag
Recommendation: fix now

`android/homecore/src/webMain/kotlin/com/spadaval/lor/concepts/queue/Queue.kt:136-137` resolves a searched `task:<id>` as `Item.Due` even when the same id is in `home.needsYou` as `flag:<id>`. Consequently its Done action uses `store.tick` (`QueuePage.kt:279-282`), whereas Done on the flag uses `store.flagDone` (`QueuePage.kt:275-276`). Only the latter clears Needs you. These are now two conflicting completion paths for the same task.

Reproduced from `#queue/demo`: search `dinner`, open “Organise Sam's birthday dinner”, tap Done, then return to the queue. The search detail is struck through, says Not done, and shows the Done notice, but the queue still shows that task's flag unstruck with a Done button and still counts 11 waiting. See `/tmp/lor-5fk6-round2/searched-flag-done.png`, `flag-still-in-queue.png` and `flag-still-in-queue.json`. No request or reload is involved; both surfaces read the same fixture-backed store.

Make task completion clear a flag consistently regardless of which surface opened the task, preserving Undo, while retaining full-list resolution for undated/future tasks. This is needed for the required task/flag interactions to agree and for clearing a task to reduce the queue the concept leads with.
