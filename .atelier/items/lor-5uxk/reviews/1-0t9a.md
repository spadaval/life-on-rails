## Finding 1: [P1] Generate prototype IDs on the HTTP origin used by the lab
Recommendation: fix now

`prototype/dashboard/src/data/store.ts:188` calls `crypto.randomUUID()`. That API is unavailable in insecure browser contexts. LoR's documented phone/PC dashboard URL is HTTP (`http://buildbot:3847`), so localhost-only checks miss the actual delivery path.

Reproduced with the built bundle and real lab CSP at `http://review.invalid:3861/lab/dashboard/`, resolving that hostname to the local scratch server. Chrome reports `isSecureContext === false` and `typeof crypto.randomUUID === "undefined"`. Adding a task displays `crypto.randomUUID is not a function`; after stopping the initial timer, Start timer leaves it stopped. On `http://127.0.0.1:3861` both actions succeed. New intents, timers, splits and links all use this helper. Use an ID generator that works on the existing HTTP lab origin; the prototype does not need server-generated IDs or a hosting change.

## Finding 2: [P2] Prevent an abandoned version load from replacing the selected version's CSS
Recommendation: fix now

`prototype/dashboard/src/shell/Shell.tsx:62-74` guards `setDirection` with `live`, but calls `linkSheets` even after the effect has been cleaned up. `linkSheets` removes the other direction's sheets and changes `data-version`. A slow earlier import can therefore strip the current version's styles after the user switches away.

Reproduced by holding the request for current's `index.ts`, switching the hash to template, waiting for Template to render, then releasing current's request. The hash and heading remain Template, but its background changes from `rgb(251, 250, 247)` to current's `rgb(12, 13, 18)`, `data-version` becomes current, and the only direction stylesheet belongs to current. This affects the core comparison dropdown once multiple directions are available. Cancel stale imports' DOM work and guard stylesheet completion/removal against a newer selection, not just the React state update.

## Finding 3: [P2] Derive People filters from the edited people rather than frozen membership
Recommendation: fix now

`prototype/dashboard/src/directions/current/server/functions/memory.ts:11-16` uses snapshot `peopleLists` membership. `prototype/dashboard/src/data/store.ts:559-567` updates cadence and only the Keeping in touch list, leaving Due a hello unchanged. It also sets `overdue_by` to null for people with no previous contact even when a cadence remains; the production reader treats them as overdue by the cadence.

In the published prototype, open People → Due a hello and set Grandpa Joe to No cadence. His overdue text disappears and he leaves Keeping in touch, but he remains in Due a hello, including after switching away and back. This makes a visible control leave contradictory screens and will affect every direction using the shared state. Recompute the relevant filter membership, order and overdue value from the current in-memory person fields.
