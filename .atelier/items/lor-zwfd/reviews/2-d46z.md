Recommendation: fix now

Omitting `allow-popups` prevents a lab document from creating a new window, but it does not sever a same-origin `window.opener` supplied when a dashboard window opens the lab, or prevent access to a dashboard `window.parent` when the lab is framed. The lab can call those windows' methods under the dashboard's policy, bypassing its own `connect-src` and `form-action`.

I reproduced both cases in system Chrome using the real `labStatic` middleware and a synthetic app. The app opened `/lab/probe.html` with `window.open` and embedded the same page with an iframe. The synthetic app recorded two `POST /_serverFn/reviewWrite` requests. The current browser test only starts the lab as a fresh top-level document, so it does not exercise either relationship.

Enforce the promised data boundary for existing window relationships as well as lab-created windows, while preserving the viewers' fixture reads and execution.
