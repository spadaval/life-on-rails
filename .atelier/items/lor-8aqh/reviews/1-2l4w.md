## Finding 1: Save the goal that search previews when adding a task
Recommendation: fix now

`android/homecore/src/webMain/kotlin/com/spadaval/lor/concepts/context/Drawer.kt:223` discards `Understood.Add.goal`. The parser removes the `#goal` word from the title and the preview displays it, but `store.addTask(u.title, u.due)` creates a task with no parent, and this path never adds a Context link. Every such task therefore lands in Loose ends regardless of the goal shown before Add.

Reproduced by typing `Example tomorrow #Offline`, tapping Add task, then searching for and opening Example: the preview shows `#Offline`, but the task opens under Loose ends. Evidence: `/tmp/lor-8aqh-review-1/goal-preview.png` and `goal-lost.png`. The brief's common search explicitly offers adding with a `#goal` and showing what it understood before acting. Resolve the goal to a context and retain that relationship with the add and its Undo; an unrecognised goal should require correction or selection rather than being displayed and silently discarded.

## Finding 2: The task's Move action only navigates to its destination
Recommendation: defer

`android/homecore/src/webMain/kotlin/com/spadaval/lor/concepts/context/Sheets.kt:470` opens the ordinary Contexts sheet without retaining the task being moved. Its `pick` callback only calls `ui.switchTo(c)` and closes the sheet; it never changes `links` or the task's parent.

Reproduced with Draft the offline maps spec → ⋯ → Move to another context… → Public beta. Public beta opens without the task, and returning to Now shows it still under Offline maps. Screenshots: `/tmp/lor-8aqh-review-1/move-context-not-moved.png` and `move-context-original.png`. This uncommon action is outside the eleven required interactions, so it need not block this comparison. Make it perform an undoable reassignment, or make the unavailable operation explicit.

## Finding 3: Visiting a context never adds it to the recent tabs
Recommendation: defer

`android/homecore/src/webMain/kotlin/com/spadaval/lor/concepts/context/Model.kt:314` builds the bar solely from the automatic current context, fixture timer labels and flagged tasks. `CtxUi.switchTo` records no visit history. Selecting Public beta through All leaves no Public beta tab, even while that context is open; after leaving it, returning requires All again. People opened as contexts likewise never become recent tabs.

The Public beta screenshot in Finding 2 demonstrates the missing tab. The brief describes recent projects and people as tabs, so this limits evaluation of that navigation model. The explicit All path and signature surface switch work, making this suitable for follow-up: retain visited contexts and include the selected one in the bar.
