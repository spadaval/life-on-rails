## Finding 3: nkm8's Done when cannot support same-pixels
Recommendation: fix now
same-pixels needs, per cell, the icon as home draws it, the wallpaper, physical size, and label ink. `.atelier/items/lor-nkm8/item.md` Goal (line 24) asks for pixels, dp, physical dpi, insets, cutout, widget snapshots, the `t3` snapshot and icons as drawn. Its Done when (lines 28–30) only stores each kind in the database and checks icons against the drawer plus `adb shell wm size` and `wm density` on both screens.

`wm density` is Android's density bucket (`densityDpi`). Calibration and real size need the screen's physical pixels-per-inch (`DisplayMetrics.xdpi` / `ydpi`). Insets and cutout are in the Goal and missing from Done when.

Label colour is `WallpaperInk` from `WallpaperManager.getWallpaperColors` (`home/Wallpaper.kt` line 99), which needs no All files access. nkm8 never uploads that hint. Recomputing it from a bitmap in wasm will not match Android's extractor, so labels go light on a dark-text wallpaper.

The wallpaper bitmap does need All files access (`design.md` line 25). That is granted on the phone. The item's emulator check is `T3_Fold_API35`. Where the op is denied, nkm8 skips the wallpaper and the web draws a plain ground, so nnn5 cannot overlay wallpaper or the ink that sits on it. Give the emulator a path that still uploads a bitmap and the ink hint (grant the op in the verify flow, or a test wallpaper the app can read).

Put each of those in Done when: physical dpi, insets and cutout, wallpaper bitmap, `HINT_SUPPORTS_DARK_TEXT` (or the chosen `Ink`), widget snapshot and preview, `t3` snapshot, and the emulator wallpaper path.
